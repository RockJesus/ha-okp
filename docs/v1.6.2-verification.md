# v1.6.2 验证：多账号不显示设备 → 已修复

## 修了什么

**问题**：实体 `unique_id` 只由 CoolKit 设备 ID 拼成。同一台设备出现在两个条目里（主账号 + 副账号）
→ 撞车 → HA 按 unique_id 去重，第二份实体被静默丢弃，界面上完全看不出来，只在日志留一行。

**修复**：`const.entity_scope(entry)` —— 按条目创建时间排序，最早的那个保持原 unique_id，
其余条目追加 `entry_id` 末 6 位。六个平台共 12 处 unique_id 全部接入。

## 两个发现（给用户看）

### 1. 第二个账号里其实有别的设备

副账号不只看到分享过来的 K5 Ultra，还看到 4 个别的实体：

```
update.xiao_du_zhi_neng_xiaodu_update
sensor.xiao_du_sao_di_ji_sao_di_ji_mo_shi
sensor.wo_shi_xiao_du_shui_mian_deng_shui_mian_deng_mo_shi
vacuum.xiao_du_sao_di_ji_sao_di_ji
```

这些不是 OKP 设备，是同一个 CoolKit 账号体系下别的品牌（「小度」扫地机、卧室吸尘器、灯具）。
按 v1.6.0 的 dp 特征识别，扫地机类被正确识别出来了。

**这是预期行为**，不是 bug：CoolKit 的 `GET /v2/device/thing` 返回账号可访问的**全部**设备。
如果不想让它们出现在 HA 里：
- 最简单：删除对应的实体（实体被禁用后不会重建）
- 或告诉我，我在 rescan 里加一个"只保留 OKP 品牌 / 只保留指定家庭"的过滤

### 2. 副账号里的 K5 Ultra 还没有实体

第二台 `vacuum` 实体是「小度」，分享进来的 K5 Ultra 反而没出现。
可能原因（需进一步确认，不猜）：

- 分享可能还没在 App 侧完成/生效；
- 或分享过来的设备 `itemType = 2`，配置流重建列表时的 OKP 设备列表里没带上它。

判断方法：主账号条目里那台 K5 Ultra 正常（`idle`、电量 100、在线），
说明设备本身没问题，问题在副账号的可见范围。下次调用 `rescan_devices` 看返回的
`discovered` 数量就能确认副账号到底能看到几台。
